## Method

`npm run benchmark -- --write` loads the committed configuration incident through the filesystem
adapter, warms the pure analysis core, and measures `analyzeEvents` with `performance.now()`. It does
not include disk I/O, browser rendering, or report serialization.

The first case runs the six-event fixture 2,000 times after 100 warmups. The scale case duplicates
the incident across 50 deterministic day-separated windows (300 events, 150 hypotheses) and runs 50
iterations after 10 warmups. No random input or network service is involved.

| Case               | Events | Hypotheses | Iterations |    Median |       p95 |       Max |
| ------------------ | -----: | ---------: | ---------: | --------: | --------: | --------: |
| Bundled incident   |      6 |          3 |      2,000 |  0.070 ms |  0.148 ms |  4.559 ms |
| 50 incident copies |    300 |        150 |         50 | 10.094 ms | 13.470 ms | 16.391 ms |

These numbers demonstrate comfortable sample-scale execution on the recorded machine; they are not
cross-platform guarantees. Browser E2E separately verifies that Worker analysis and initial render
complete within normal Playwright expectations. Re-run the command on a target system when latency
budgets matter.
